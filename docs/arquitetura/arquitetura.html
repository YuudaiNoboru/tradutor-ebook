Interação: Totalmente mediada pela TUI Textual e pelo assistente gráfico de instalação do Windows.

Acessos: Configuração segura de chaves (Keyring/AES), seleção de livros, estimativa pré-voo, acompanhamento ao vivo e atualização visual transparente.

Ator: Sistema (Automações / CI)

Interação: Processamento concorrente assíncrono em background, validação atômica de instalador e esteiras contínuas.

Acessos: Parsing cirúrgico XHTML, isolamento de placeholders {{N}}, sanitização anti-mojibake, tradução com rate-limit, reordenação de índices, checagem SHA-256 e verificação de contratos estritos.

Isolamento: Provedores HTTP são desacoplados via adaptadores isolados no pacote providers/.

Ator: Desenvolvedor (Mantenedor)

Interação: Tooling unificado via CLI do Hatch, Git hooks nativos, scripts de build Inno Setup e guias declarativos.

Acessos: Suíte de testes (gate >= 95%), checagens estritas de tipagem (Mypy), testes de mutação (Mutmut), linter de arquitetura (Import-Linter), detecção de dead code (Vulture), testes E2E com Textual Pilot e build do instalador Windows.

Isolamento: Zero commits manuais em arquivos protegidos de versão ou changelog.

Pacote domain/ — Coesão Funcional Pura

Alta Coesão

Todas as funções e dataclasses em domain/ executam exclusivamente transformações matemáticas e validações puras de regras de negócio (cálculo de tokens/preço, matching de regras de proteção declarativas, integridade de placeholders e sanitização anti-mojibake). Zero dependências de rede, I/O ou bibliotecas de terceiros.

Pacote epub/ — Coesão Sequencial e Funcional

Alta Coesão

Responsável exclusivo pela desmontagem, análise cirúrgica, reordenação de índices (index_rebuilder.py) e remontagem de arquivos EPUB. A saída do descompactador alimenta diretamente o segmentador e o escritor, formando um fluxo sequencial estrito e determinístico.

Pacote translate/ — Coesão de Comunicação & Orquestração

Alta Coesão

Agrupa os serviços que coordenam o fluxo de tradução assíncrona, rate limiting, controle de custos, persistência do cache estado.json e geração de passadas de glossário e guia de estilo.

Pacote providers/ — Coesão de Comunicação (Adapters)

Alta Coesão

Adapters isolados para comunicação HTTP externa. Cada provedor implementa o contrato Translator ou MachineTranslationProvider sem vazar particularidades de rede para a camada de domínio.

Pacote installer/ & infra/updater.py — Coesão Funcional (Distribuição Segura)

Alta Coesão

Isolamento completo da sistemática de empacotamento, instalação per-user e atualização segura. O subsistema detecta o modo de execução, baixa instaladores validando hash SHA-256 e delega ao Inno Setup a substituição atômica de arquivos, sem uso de scripts ocultos em PowerShell.

Pacote tests/arch/ & Harness — Coesão Funcional (Fitness Sensors)

Alta Coesão

Validação contínua e determinística das fronteiras de arquitetura (import-linter e AST), contratos estritos de tipagem (mypy), segurança de dependências (pip-audit) e eficácia semântica de asserções (mutmut).

Registros de Decisões Arquitetônicas (ADRs)

Histórico formal de decisões críticas de design e seus trade-offs.

ADR-001: Arquitetura Hexagonal com Separação Estrita de Domínio e Adapters

Aprovada
Contexto
Necessidade de garantir altíssima testabilidade (gate >= 95%) e isolamento total entre regras de negócio, interface de usuário e chamadas de API externas.
Decisão
O módulo domain/ não depende de nenhuma biblioteca externa ou adapter de I/O. Credenciais e chaves nunca passam pelo modelo de domínio.
Consequências
Positivas: 100% de testabilidade do domínio sem mocks complexos; facilidade para plugar novos provedores ou interfaces.
Negativas: Camada adicional de mapeamento entre adapters e domínio.

ADR-002: Proteção Determinística de Markup por Placeholders

Aprovada
Contexto
LLMs podem corromper tags XHTML, código, scripts, fórmulas matemáticas e âncoras durante o processo de tradução.
Decisão
Substituir todo conteúdo protegido por tokens determinísticos {{N}} antes do envio, validando estritamente a fidelidade pós-resposta via is_formatting_faithful.
Consequências
Positivas: 100% de integridade estrutural e visual no EPUB gerado.
Negativas: Requer rejeição e reenvio caso o modelo de IA altere ou omita um placeholder.

ADR-003: Interface TUI Reativa com Executável Standalone para Windows

Aprovada
Contexto
Entregar uma experiência fluida no terminal e permitir distribuição sem necessidade de instalar Python no Windows.
Decisão
Construir a interface com Textual e empacotar via PyInstaller para Windows com atualizador automático integrado via GitHub Releases.
Consequências
Positivas: Usabilidade moderna no terminal e facilidade de distribuição para usuários finais.
Negativas: Necessidade de pipeline específico de build e testes para executáveis congelados.

ADR-004: Armazenamento Criptografado de Chaves via Keyring e Fallback AES

Aprovada
Contexto
Garantir a segurança das chaves de API dos usuários (filosofia BYOK) em qualquer ambiente.
Decisão
Priorizar o cofre nativo do sistema operacional (keyring). Se indisponível, utilizar arquivo local cifrado com AES-GCM via cryptography.
Consequências
Positivas: Zero chaves em texto claro em disco; portabilidade garantida em servidores headless ou containers.
Negativas: Dependência de chave/segredo derivado para o cofre AES fallback.

ADR-005: Suporte Dual a Famílias de Provedores (LLM BYOK e MT sem Chave)

Aprovada
Contexto
Atender tanto usuários avançados que buscam máxima qualidade com LLMs quanto usuários que preferem tradução rápida e gratuita sem cadastro.
Decisão
Implementar duas famílias de adaptadores (llm e machine_translation) com polimorfismo limpo sob a mesma porta de tradução.
Consequências
Positivas: Máxima flexibilidade de escolha para o leitor.
Negativas: Lógica de batching diferenciada por família (tokens para LLMs vs limites de caracteres para Web MT).

ADR-006: Preservação Estrutural Determinística e Reconstrução Semântica Multilíngue de Índices EPUB

Aprovada
Contexto
Índices remissivos traduzidos mantinham a ordem alfabética do inglês original; imagens inline e âncoras posicionais vazias eram corrompidas por LLMs; e o apêndice de glossário perdia o estilo CSS do livro.
Decisão
1. Estender política de proteção declarativa para mídia, classes CSS de código e âncoras vazias.
2. Criar epub/index_rebuilder.py para parser, tradução e reordenação alfabética por colação Unicode (NFD) agnóstica de idioma.
3. Integrar sanitização e filtro anti-mojibake em domain/quality.py.
4. Injetar folhas de estilo do manifesto OPF em documentos sintéticos.
Consequências
Positivas: 100% de imagens preservadas; 0 links quebrados; índice perfeitamente reordenado de A a Z em qualquer idioma; eliminação de artefatos visuais de encoding.
Negativas: Passo adicional de decomposição da árvore de termos em arquivos de índice.

ADR-007: Adoção de Harness de Engenharia com Sensores Determinísticos e Guides Feedforward

Aprovada
Contexto
A aceleração do desenvolvimento com agentes de IA e múltiplos colaboradores exigia salvaguardas que impedissem regressões de tipagem, desvios na Arquitetura Hexagonal, asserções de testes ineficazes e dependências com CVEs conhecidas.
Decisão
1. Impor tipagem estrita com mypy --strict no Hatch e CI.
2. Impor contratos hexagonais via import-linter e suíte tests/arch/.
3. Configurar testes de mutação com mutmut nos 4 módulos críticos de integridade.
4. Adotar hook Git nativo pre-commit automatizado no hatch run setup.
5. Integrar pip-audit e vulture para segurança e detecção de dead code.
6. Adotar suíte de testes E2E assíncronos com Textual Pilot.
7. Publicar guia declarativo para novos provedores em docs/guias/novo-provedor.md.
Consequências
Positivas: Blindagem determinística da arquitetura; feedback precoce aos agentes de IA antes do commit e no CI; verificação semântica profunda dos testes; ausência de dependências vulneráveis.
Negativas: Pequeno incremento no tempo do CI (~30s a 1min) e necessidade de manter anotações de tipos rigorosas em todo código novo.

ADR-008: Sistemática de Instalação Nativa no Windows (Inno Setup) e Atualização Dual com Eliminação de Scripts Ocultos

Aprovada
Contexto
O antigo atualizador em segundo plano utilizava scripts PowerShell ocultos (update_helper.ps1 com -ExecutionPolicy Bypass), gerando disparos de falso-positivo no Windows Defender e bloqueios de SmartScreen. Além disso, usuários de Windows não contavam com atalhos de Área de Trabalho, Menu Iniciar ou desinstalador padrão.
Decisão
1. Adotar Inno Setup para compilar o instalador oficial tradutor-ebook-setup.exe configurado para instalação per-user em %LOCALAPPDATA%\Programs\tradutor-ebook sem necessidade de elevação de UAC.
2. Eliminar completamente scripts PowerShell ocultos do repositório.
3. Implementar detecção de modo no aplicativo: no Modo Instalado (presença de unins000.exe), a atualização baixa o setup com validação SHA-256 e executa o assistente visual com saída graciosa; no Modo Portátil (executável avulso tradutor.exe), abre a release no navegador.
Consequências
Positivas: Eliminação total de alertas de segurança do Windows Defender; instalação limpa sem privilégios de admin; criação de atalhos e desinstalação padrão pelo Painel do Windows; experiência de atualização transparente com assistente gráfico.
Negativas: No modo portátil, o usuário precisa baixar e substituir o binário manualmente via navegador.

Estilo Arquitetural & Matriz de Trade-offs

Análise de compromissos arquitetônicos conforme Richards & Ford.

Estilo: Monolito Modular Hexagonal

O projeto adota uma arquitetura em Monolito Modular com Portas e Adaptadores (Hexagonal) com Harness de Engenharia Integrado e Distribuição Nativa Windows.

Essa escolha prioriza baixo custo operacional, altíssima velocidade de teste local, simplicidade de deploy, integridade transacional de arquivos, segurança contra falso-positivos e blindagem automática contra desvios arquiteturais.

Princípio Chave:

O núcleo de domínio é 100% puro e agnóstico de infraestrutura. Todas as dependências externas apontam para dentro em direção ao domínio e são validadas computacionalmente a cada commit.
